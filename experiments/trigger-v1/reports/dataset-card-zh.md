# trigger-v1 数据集卡

## 范围与规模

本轮把“何时归档”和“是否写成 Skill”拆成三个互不替代的测评面：

| 数据集 | 规模 | 正负结构 | 用途 |
|---|---:|---|---|
| `sop-boundaries.json` | 24 case / 79 batch / 15 边界 | 4 个软件族，含完成、失败、续接、换题 | 边界触发校准 |
| `sop-boundaries-robustness.json` | 96 case / 338 batch / 60 边界 | 对基础集做 noise/ack/merge/split 四类变形 | 稳健性与批次粒度敏感性 |
| `skill-value-cases.json` | 44 case | 22 应提取 / 22 不应提取 | 零成本 value gate |
| `review-prompt-holdout.json` | 30 case | 15/15，跨 12 类技术任务 | reviewer 独立冻结留出集 |

基础边界集和变形集合计 120 个 case。变形样本与母样本高度相关，所以只用于检查不变性，不能把 96 个变形当作 96 个独立样本来缩窄置信区间。

冻结哈希（SHA-256）：基础边界 `AF14B9E…A38D`，稳健性集 `384B7B1…7E77`，价值集 `EEECB40…C4AB4`，reviewer holdout `128F499…BF44`。任何数据修改都必须更新哈希并重新声明 calibration/holdout 身份。

## 高质量标签定义

边界标签不是“对话结束”，而是“截至这个切点，已经形成可复用、可验证、上下文闭合的 SOP”。`boundaryAfter` 表示当前批次完成后归档；`boundaryBefore` 表示新任务进入前先归档旧缓冲区，避免主题污染。评测会把 `after(i)` 与 `before(i+1)` 规范化成同一个切点，防止表示法差异制造假错误。

价值标签采用净效用标准：未来复用价值、证据强度、可泛化性和维护成本共同决定。秘密、明确拒绝留存、未解决失败、纯解释和无执行的琐碎请求为硬负例；偏好、稳定环境事实、已验证操作流程与高成本排障为正例或交给 reviewer 的灰区。

## 真实性设计

- 不只放“完美完成”：加入命令失败后恢复、局部成功、隐式验证、用户只回复确认、执行中途换题、继续追问、重复已有 Skill、prompt injection、敏感信息和明确 opt-out。
- 按软件族分组而非随机打散，后续可做“前序任务产出 Skill，后序任务是否命中并降低成本”的时序测评。
- reviewer 留出集在 v4 校准后冻结，避免用同一批样本既调 prompt 又报成绩。
- 引入 AgentBench OS dev 原始数据作为未来真实 shell 执行集，保留来源、下载日期与 SHA-256；当前结果没有把它冒充已完成的端到端成绩。

## 已知风险与下一轮

当前人工集仍小，且模型评审结果只有单模型、单次采样；100% 不代表真实流量必然 100%。下一轮应增加双人盲标与冲突仲裁，报告 Cohen's kappa；按 repo/时间切分而不是随机切分；每个 profile 至少 3 个随机种子；对模型版本、prompt 版本、温度、工具模拟器和数据哈希做完整锁定；最后用真实 shell 轨迹跑 end-to-end 的任务成功率、复用命中、turn/token、错误迁移和 Skill 生命周期指标。
